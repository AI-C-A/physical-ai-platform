# 시뮬레이션 수집

수집 콘솔에서 **시뮬레이션 수집** 화면으로 이동해, VR(Meta Quest)로 WebXR 시뮬레이션(판교 정비창의 8개 임무 스테이션)에서 작업을 수행하고, 그 화면과 수집 데이터를 PC 콘솔에서 함께 본다. 시뮬레이션 자체(WebXR Action Annotation Factory)는 별도 저장소다.

## 접속 방식 — VR로 들어가고 PC는 받아온 화면을 띄운다

1. **MLOps → 수집**에서 진행 중인 휴머노이드 세션을 연다.
2. 수집 콘솔의 **장치** 탭 → **시뮬레이션 수집**을 누른다(`/mlops/collection/:sessionId/simulation`).
3. 화면의 **VR 접속 안내**에 **방 코드**와 **헤드셋 접속 주소**가 뜬다.
4. Quest 브라우저에서 그 주소를 열고(또는 로비 방 코드 입력란에 코드를 입력), **VR로 입장** 후 스테이션 받침대의 START로 작업을 시작한다.
5. PC 콘솔은 같은 방에 **관전(spectator)** 으로 붙어 헤드셋 시점의 화면을 그대로 띄우고, 수집 데이터를 실시간으로 보여준다. **PC로도 참가**로 데스크톱에서 직접 작업해 볼 수도 있다.

방 코드는 수집 세션 ID에서 만들어지는 짧은 코드이며 세션마다 고정이다(헷갈리는 0/O/1/I/5/S 제외). **VR 접속 안내**의 *방 코드 바꾸기* 로 임의 코드를 쓸 수 있다(주소의 `?room=`).

## 화면 배치

시뮬레이션(관전)·수집 자세·실시간 수집 데이터·수집 카메라 타일이 개수에 맞춰 자동 배치된다. 카메라를 연결하면 타일이 늘며 배치가 다시 잡히고, 각 타일 오른쪽 위의 버튼으로 한 화면을 **크게 보기**/원래대로 할 수 있다(크게 보는 동안에도 다른 화면은 계속 돌아간다).

- **시뮬레이션 · 판교 정비창** — 헤드셋 시점을 비추는 관전 화면(iframe).
- **수집 자세** — 브리지가 보내는 머리·양손 자세를 정면(X·Y)·평면(X·Z)으로 그린 시각화. 손 관절 25점이 오면 손가락 골격을 그린다.
- **실시간 수집 데이터** — 참가자, 프레임·이벤트·추적 물체·에피소드, 임무 단계 진행, 손 추적 좌표, 조작 이벤트 로그.
- **수집 카메라 · Body Segmentation** — 브라우저 카메라 영상과 인물 세그멘테이션(기존 수집 콘솔과 동일).

## 데이터가 콘솔에 도달하는 경로

PC 콘솔은 릴레이(WebSocket)에 직접 붙지 않고, **관전 iframe이 부모 창으로 보내는 postMessage 스냅샷**만 읽는다. iframe은 시뮬레이션의 기존 협업 릴레이로 방에 들어가 VR 작업자를 미러링하고, 그 상태(참가자·임무 단계·자세·이벤트·수집 카운트)를 콘솔로 올린다. 콘솔은 `event.origin`이 시뮬레이션 origin과 같은 메시지만 받는다. 그래서 PC에서 릴레이가 직접 닿지 않아도, 화면만 뜨면 값이 보인다.

WebXR 쪽 추가(기존 코드를 건드리지 않는 선):
- `src/net/MonitorBridge.js` — 임베드(`window.parent !== window`)일 때만 스냅샷을 postMessage로 올린다. 단독 실행 시 아무 일도 하지 않는다.
- 관전 진입은 기존 `?spectate=1`을 사용한다(헤드셋 시점을 그대로 비추는 모드).
- 관전자가 러너의 프레임·이벤트 수를 알 수 있도록 협업 `task_state`에 러너의 수집 카운트를 실어 보낸다.

## 접속 주소 설정

Quest와 PC가 같은 주소로 들어가야 같은 방을 공유한다. 기본값은 Tailscale Funnel 주소이며 `.env.local`의 `VITE_SIMULATION_ORIGIN`으로 바꾼다. 프로토콜·호스트·포트까지만 입력한다.

```
VITE_SIMULATION_ORIGIN=https://orca.tail58a6fa.ts.net
```

## 시뮬레이션 서버(별도 저장소)

시뮬레이션과 협업 릴레이는 WebXR 저장소에서 실행한다. 릴레이는 Vite dev·preview 서버에 플러그인으로 붙어 페이지와 같은 포트(`/party`)로 동작한다. **릴레이가 붙지 않은 채 오래 떠 있던 서버는 다시 시작해야 한다**(그렇지 않으면 관전 iframe이 방에 들어가지 못해 참가자·데이터가 뜨지 않는다). `MonitorBridge`를 포함하려면 최신 코드로 다시 빌드한다.

```
npm run build && npm run preview   # dist를 서빙하며 /party 릴레이도 함께 붙는다
# 또는 개발 중
npm run dev:funnel                 # Tailscale Funnel + Vite dev
```
